# test — 내부평가 성과관리

폐쇄망 서버에서 사용할 직원 계정·근무지·담당지표 관리 모듈의 초기 구현입니다.
Python 3.11 이상과 표준 라이브러리만 사용하며 외부 API, CDN, 패키지 설치가 필요하지 않습니다.


## GitHub에서 바로 실행하기

[![Codespaces에서 실행](https://github.com/codespaces/badge.svg)](https://codespaces.new/sungwoo83/test?quickstart=1)

1. 위 버튼을 누르고 GitHub 계정으로 로그인한 뒤 **Create codespace**를 선택합니다.
2. 환경 준비가 끝나면 프로그램이 자동으로 시작되고 8080 포트를 전달합니다.
3. 화면이 자동으로 열리지 않으면 하단 **PORTS**에서 **8080 → Open in Browser**를 선택합니다.
4. 프로그램 화면에서 회원가입한 후 로그인, 근무지 변경, 담당지표 수정을 사용할 수 있습니다.

기존 Codespace에는 최신 변경을 반영한 뒤 **Codespaces: Rebuild Container**를 실행합니다.
자동 실행에 실패하면 터미널에서 `python .devcontainer/start.py`를 실행합니다.
시작 로그는 `data/codespaces.log`에 기록됩니다.

Codespaces는 GitHub가 제공하는 온라인 개발·시연 환경입니다. 계정의 이용 가능 여부와 사용량 한도가 적용됩니다.
포트 공개 범위는 기본 Private를 유지하고, 테스트용 계정·비밀번호를 사용하세요.
DB는 해당 Codespace의 data 폴더에 남지만, Codespace를 삭제하면 함께 삭제됩니다. 다른 Codespace와 DB를 공유하지 않습니다.
실제 직원이 사용하는 폐쇄망 배포는 아래 내부망 실행 절차로 진행합니다.

## 실행

```bash
python app.py
```

브라우저에서 http://127.0.0.1:8080 에 접속합니다. Windows에서는 `py app.py`를 사용할 수 있습니다.

**사용자의 공개 업로드 승인에 따라 실제 부서 55개·성과지표 165개를 `catalog.json`에 포함했습니다.** 제공된 표준양식에서 추출한 기준자료입니다. 원본 PDF·엑셀과 계정 DB는 포함하지 않습니다.
`catalog.json`이 없으면 `catalog.example.json`의 가상 예시 데이터를 읽고 화면에 예시 데이터임을 표시합니다.
조직 표시명과 원문 적용부서명이 다른 경우 `indicator_department`로 연결합니다.
예시에서 실제 기준자료로 전환할 때는 예시로 생성한 계정 DB를 분리하여 운영해야 합니다.

## 제공 기능

- 사번·비밀번호 회원가입, 사번 앞자리 0 보존 및 중복 차단
- 근무지별 담당지표 복수 선택과 서버 DB 저장
- 로그인 시 저장한 근무지·담당지표 복원
- 첫 화면에서 근무지 변경과 담당지표 수정
- 근무지 변경 시 지표 재선택, 변경 전후 설정·변경시각 보존
- 비밀번호 scrypt 해시, 서버 세션, CSRF 검증, 동시수정 감지
- 로그아웃·8시간 세션 만료, 로그인 실패 횟수 제한
- 수퍼관리자·지정 부서 관리자·직원 권한 구분
- 월별 실적 입력, 관리자 실적 조정, 월 마감·마감 해제와 변경 이력
- 수퍼관리자의 전체 지표 정의 수정과 직원 권한 지정

선택한 담당지표는 본인의 업무 설정입니다. 관리자·평가자 권한을 부여하지 않습니다.

## 관리자 권한과 월별 관리

| 구분 | 범위 | 기능 |
| --- | --- | --- |
| 직원 | 본인 근무지의 담당지표 | 월별 실적 입력·수정, 본인 업무 설정 |
| 관리자 | 수퍼관리자가 지정한 부서 1곳 | 해당 부서의 실적 조회·조정, 월 마감, 부서 변경 이력 조회 |
| 수퍼관리자 | 전체 평가대상 부서 | 전체 지표 수정, 직원 권한·관리 부서 지정, 실적 조정, 월 마감·해제, 전체 변경 이력 조회 |

수퍼관리자는 **성과혁신실 또는 AI정보융합실** 소속 계정에 지정할 수 있습니다. 해당 부서 소속이어도 자동으로 권한을 부여하지 않습니다. 성과혁신실은 평가총괄 운영 부서로 등록되며 담당지표 없이 가입할 수 있습니다.
회원가입에서는 모든 계정을 직원으로 생성합니다. 요청값을 조작해서 관리자 권한을 얻을 수 없습니다.
관리자의 권한 범위는 개인 근무지와 별도로 지정하므로, 근무지 변경만으로 다른 부서의 관리자 권한이 생기지 않습니다.

### 최초 수퍼관리자 지정

1. 프로그램의 회원가입에서 근무지를 **성과혁신실 또는 AI정보융합실**로 선택하여 담당자가 가입합니다. AI정보융합실은 기존 방식대로 담당지표도 선택합니다.
2. 서버 또는 Codespaces 터미널에서 실제 가입 사번으로 다음 명령을 실행합니다.

```bash
python manage.py bootstrap-superadmin --employee-id 가입한사번
```

3. 해당 계정으로 다시 로그인하면 수퍼관리자 화면이 나타납니다.
4. 수퍼관리자가 직원 목록에서 부서별 관리자를 지정하고 관리 부서를 선택합니다.

이미 수퍼관리자가 있으면 초기 지정 명령은 거절됩니다. 이후 추가 지정은 웹의 권한 관리에서 수행합니다.
기본 관리자 사번·비밀번호는 제공하지 않습니다. 마지막 수퍼관리자는 해제할 수 없습니다.
권한 변경은 해당 직원의 기존 세션을 만료시키므로 다시 로그인해야 합니다.

### 월별 실적과 마감

- 연도·월·대상 부서로 조회하고, 지표별 월간 실적을 입력합니다.
- 관리자가 조정하면 원래 실적과 조정값을 별도로 저장합니다. 반영 실적은 조정값이 있으면 조정값, 없으면 입력 실적입니다.
- 관리자가 조정한 실적은 직원이 덮어쓸 수 없습니다. 관리자가 조정을 해제한 후 원래 입력 실적을 수정할 수 있습니다.
- 마감은 지정 부서·해당 월에 적용합니다. 마감 후 수퍼관리자를 포함한 모든 사용자의 실적 입력·조정을 차단합니다.
- **마감 해제는 수퍼관리자만** 할 수 있습니다. 입력·조정·마감·해제·지표 수정·권한 변경에 사유와 변경 전후 값, 처리자, 시각을 남깁니다.
- 지표 수정은 지표명·단위·목표·배점·산식 설명을 지원합니다. 지표의 적용 부서·평가유형 변경이나 신설·삭제는 아직 제공하지 않습니다.
- 기존 월별 실적에는 최초 입력 당시 지표 정의를 보존합니다. 지표 수정으로 과거 실적이나 점수를 자동 재산정하지 않습니다.
- 목표·배점·산식 설명은 기준정보입니다. 편람의 복합 산식·예외를 적용하는 점수 계산 엔진은 후속 개발 범위입니다.
- 월 마감은 입력 잠금이며 전체 지표의 제출 완료를 자동 인정하는 절차는 아닙니다.
- 기존 계정 DB는 시작 시 자동으로 스키마를 확장하며 기존 계정의 권한은 직원으로 유지합니다.


## 내부망 실행

사내 인증기관에서 발급한 인증서와 키를 사용합니다.

```bash
python app.py --host 0.0.0.0 --port 8443 --cert server.crt --key server.key
```

직원은 인증서 이름과 일치하는 내부 DNS 주소로 접속합니다. 내부 서버 방화벽과 서비스 자동시작은 운영환경에 맞게 설정합니다.
HTTP 기본 실행은 로컬 확인용입니다. 직원이 접속하는 내부망 환경은 HTTPS로 구성합니다.

계정·설정·변경 이력은 `data/performance.sqlite3`에 저장됩니다. 서버를 종료하고 data 폴더를 백업하거나 운영 중 SQLite backup API를 사용합니다.
비밀번호나 세션 원문은 저장하지 않습니다. 서버 관리자는 DB와 인증서 개인키 접근권한을 제한해야 합니다.

## 테스트

```bash
python -m unittest -v test_app test_management
```

회원가입부터 재로그인 후 복원, 근무지 변경 이력, 서버 검증, 계정별 접근 분리, 만료 세션, 로그인 시도 제한을 검증합니다.
브라우저 화면 확인, 실제 내부망 배포 및 부하검증은 아직 수행하지 않았습니다.

## 후속 개발 범위

직원 여부 확인을 위한 인사명부 대조·가입 승인, 비밀번호 재설정, 계정 비활성화,
증빙파일 업로드·평가점수 자동 계산·평가위원 채점은 아직 포함하지 않았습니다.
사번을 직접 입력하는 가입 방식이므로 실제 직원 운영 전 계정 확인 절차를 구성해야 합니다.

향후 실적 데이터에는 작성 당시 부서와 지표·양식 버전을 별도로 저장해야 하며,
인사이동 시 과거 실적의 소속이 바뀌지 않도록 설계합니다.
