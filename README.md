# test — 내부평가 성과관리

폐쇄망 서버에서 사용할 직원 계정·근무지·담당지표 관리 모듈의 초기 구현입니다.
Python 3.11 이상과 표준 라이브러리만 사용하며 외부 API, CDN, 패키지 설치가 필요하지 않습니다.


## GitHub에서 바로 실행하기

[![Codespaces에서 실행](https://github.com/codespaces/badge.svg)](https://codespaces.new/sungwoo83/test?quickstart=1)

1. 위 버튼을 누르고 GitHub 계정으로 로그인한 뒤 **Create codespace**를 선택합니다.
2. 환경 준비가 끝나면 프로그램이 자동으로 시작되고 8080 포트를 전달합니다.
3. 화면이 자동으로 열리지 않으면 하단 **PORTS**에서 **8080 → Open in Browser**를 선택합니다.
4. 프로그램 화면에서 회원가입한 후 로그인, 근무지 변경, 담당지표 수정을 사용할 수 있습니다.

기존 Codespace에는 최신 변경을 반영한 뒤 **Codespaces: Rebuild Container**를 실행합니다.
자동 실행에 실패하면 터미널에서 `python .devcontainer/start.py`를 실행합니다.
시작 로그는 `data/codespaces.log`에 기록됩니다.

Codespaces는 GitHub가 제공하는 온라인 개발·시연 환경입니다. 계정의 이용 가능 여부와 사용량 한도가 적용됩니다.
포트 공개 범위는 기본 Private를 유지하고, 테스트용 계정·비밀번호를 사용하세요.
DB는 해당 Codespace의 data 폴더에 남지만, Codespace를 삭제하면 함께 삭제됩니다. 다른 Codespace와 DB를 공유하지 않습니다.
실제 직원이 사용하는 폐쇄망 배포는 아래 내부망 실행 절차로 진행합니다.

## 실행

```bash
python app.py
```

브라우저에서 http://127.0.0.1:8080 에 접속합니다. Windows에서는 `py app.py`를 사용할 수 있습니다.

**사용자의 공개 업로드 승인에 따라 실제 부서 55개·성과지표 165개를 `catalog.json`에 포함했습니다.** 제공된 표준양식에서 추출한 기준자료입니다. 원본 PDF·엑셀과 계정 DB는 포함하지 않습니다.
`catalog.json`이 없으면 `catalog.example.json`의 가상 예시 데이터를 읽고 화면에 예시 데이터임을 표시합니다.
조직 표시명과 원문 적용부서명이 다른 경우 `indicator_department`로 연결합니다.
예시에서 실제 기준자료로 전환할 때는 예시로 생성한 계정 DB를 분리하여 운영해야 합니다.

## 회원가입 이름 입력

회원가입 시 **사번·이름·비밀번호·근무지·담당지표**를 입력합니다. 이름은 앞뒤 공백을 제거하고 1~100자로 저장합니다.
로그인 시에는 사번과 비밀번호만 사용합니다. 저장한 이름은 로그인 상단, 관리자 직원 목록, 월별 실적 확인과 XLSX의 성명에 표시합니다.
기존에 이름 없이 가입한 계정도 사번·비밀번호로 로그인할 수 있습니다.

## 제공 기능

- 사번·이름·비밀번호 회원가입, 사번 앞자리 0 보존 및 중복 차단
- 근무지별 담당지표 복수 선택과 서버 DB 저장
- 로그인 시 저장한 근무지·담당지표 복원
- 첫 화면에서 근무지 변경과 담당지표 수정
- 근무지 변경 시 지표 재선택, 변경 전후 설정·변경시각 보존
- 비밀번호 scrypt 해시, 서버 세션, CSRF 검증, 동시수정 감지
- 로그아웃·8시간 세션 만료, 로그인 실패 횟수 제한
- 수퍼관리자·지정 부서 관리자·직원 권한 구분
- 월별 실적 입력, 관리자 실적 조정, 월 마감·마감 해제와 변경 이력
- 수퍼관리자의 전체 지표 정의 수정과 직원 권한 지정

선택한 담당지표는 본인의 업무 설정입니다. 관리자·평가자 권한을 부여하지 않습니다.

## 관리자 권한과 월별 관리

| 구분 | 범위 | 기능 |
| --- | --- | --- |
| 직원 | 본인 근무지의 담당지표 | 수치·서술 실적, 진행상태, 향후계획 입력, 증빙 업로드 |
| 관리자 | 수퍼관리자가 지정한 부서 1곳 | 모든 소속 직원 실적 확인·수정, 목표·가중치 설정, 월 마감·해제, XLSX 다운로드 |
| 수퍼관리자 | 전체 평가대상 부서 | 전체 지표 수정, 직원 권한·관리 부서 지정, 실적 조정, 월 마감·해제, 전체 변경 이력 조회 |

수퍼관리자는 **성과혁신실 또는 AI정보융합실** 소속 계정에 지정할 수 있습니다. 해당 부서 소속이어도 자동으로 권한을 부여하지 않습니다. 성과혁신실은 평가총괄 운영 부서로 등록되며 담당지표 없이 가입할 수 있습니다.
회원가입에서는 모든 계정을 직원으로 생성합니다. 요청값을 조작해서 관리자 권한을 얻을 수 없습니다.
관리자의 권한 범위는 개인 근무지와 별도로 지정하므로, 근무지 변경만으로 다른 부서의 관리자 권한이 생기지 않습니다. 월별 실적 확인 화면과 XLSX 다운로드에서도 같은 범위를 서버에서 검사합니다.

### 최초 수퍼관리자 지정

1. 프로그램의 회원가입에서 근무지를 **성과혁신실 또는 AI정보융합실**로 선택하여 담당자가 가입합니다. AI정보융합실은 기존 방식대로 담당지표도 선택합니다.
2. 서버 또는 Codespaces 터미널에서 실제 가입 사번으로 다음 명령을 실행합니다.

```bash
python manage.py bootstrap-superadmin --employee-id 가입한사번 --set-password
```

3. 콘솔에 표시되는 비밀번호·확인 입력란에 사용할 수퍼관리자 비밀번호를 입력합니다. 입력값은 화면에 표시하지 않습니다.
4. 해당 계정으로 다시 로그인하면 수퍼관리자 화면이 나타납니다.
5. 수퍼관리자가 **관리자 권한 제어** 화면의 직원 목록에서 부서별 관리자를 지정하고 관리 부서를 선택합니다. 관리자와 직원은 관리자 권한을 부여할 수 없습니다.

이미 수퍼관리자가 있으면 초기 지정 명령은 거절됩니다. 이후 추가 지정은 웹의 관리자 권한 제어에서 수행합니다.
수퍼관리자 비밀번호는 서버 DB에 해시로 저장하며 공개 저장소·명령행 인수·감사이력에는 남기지 않습니다.
수퍼관리자 콘솔 설정은 6~128자를 지원하며 일반 직원 회원가입의 10자 이상 기준은 유지합니다.
이미 지정한 수퍼관리자의 비밀번호는 서버/Codespaces 콘솔에서 다음 명령으로 설정합니다.

```bash
python manage.py set-superadmin-password --employee-id 수퍼관리자사번
```

변경하면 해당 계정의 기존 로그인 세션이 만료됩니다. 이 명령은 직원 계정을 관리자로 승격하지 않습니다. 마지막 수퍼관리자는 해제할 수 없습니다.
권한 변경은 해당 직원의 기존 세션을 만료시키므로 다시 로그인해야 합니다.


가입 전 최초 수퍼관리자 계정을 직접 생성하려면 서버 또는 Codespaces 콘솔에서 실행합니다.
소속 부서 ID는 AI정보융합실 `ORG-004`, 성과혁신실 `SYS-PERFORMANCE`입니다.

```bash
python manage.py create-superadmin --employee-id 수퍼관리자사번 --department-id ORG-004
```

이어지는 숨김 입력란에 사용할 비밀번호를 두 번 입력합니다. 비밀번호를 명령행 인수로 전달하지 않습니다.
이 명령은 기존 수퍼관리자가 없는 서버에서만 실행되며, 기존 계정을 덮어쓰지 않습니다.
GitHub 저장소에는 실행 코드만 저장되며 실제 계정은 이 명령을 실행한 서버/Codespace의 DB에 생성됩니다.

추가 수퍼관리자를 서버 운영자가 생성해야 할 때는 다음 명령을 사용합니다. 기존 수퍼관리자는 유지됩니다.

```bash
python manage.py add-superadmin --employee-id 추가사번 --department-id SYS-PERFORMANCE --name 담당자성명
```

이는 서버 콘솔 전용 기능입니다. 웹에서 관리자 권한을 부여·변경하는 기능은 수퍼관리자에게만 허용됩니다.
실제 직원 사번·성명·비밀번호는 저장소의 기본 설정으로 배포하지 않으며 각 실행 서버의 DB에 보관합니다.


### 로그인은 되지만 수퍼관리자로 표시되지 않을 때

계정 권한은 각 서버/Codespace의 DB에 저장되며 GitHub 코드만 업데이트해서는 바뀌지 않습니다.
서버 또는 Codespaces 터미널에서 다음 명령으로 이미 가입한 계정의 수퍼관리자 권한을 복구합니다.
다른 수퍼관리자가 이미 있어도 실행할 수 있습니다.

```bash
git pull --ff-only
python manage.py promote-superadmin --employee-id 대상사번 --department-id SYS-PERFORMANCE --name 담당자성명
```

AI정보융합실은 `--department-id ORG-004`를 사용합니다. 소속을 지정하지 않으면 기존 소속을 검사·유지합니다.
**기존 비밀번호·실적·증빙과 다른 관리자의 권한은 유지**하고, 대상 계정의 기존 로그인 세션만 만료시킵니다.
명령 실행 후 로그아웃하고 기존 비밀번호로 다시 로그인하면 수퍼관리자 메뉴가 표시됩니다.
이 기능은 신뢰할 수 있는 서버 콘솔 전용이며 회원가입이나 웹에서 본인이 권한을 올리는 기능이 아닙니다.
비밀번호도 새로 설정해야 하는 경우에만 `--set-password`를 추가합니다.

### 월별 실적과 마감

- 연도·월·대상 부서로 조회하고, 지표별 월간 실적을 입력합니다.
- 관리자가 조정하면 원래 실적과 조정값을 별도로 저장합니다. 반영 실적은 조정값이 있으면 조정값, 없으면 입력 실적입니다.
- 관리자가 조정한 실적은 직원이 덮어쓸 수 없습니다. 관리자가 조정을 해제한 후 원래 입력 실적을 수정할 수 있습니다.
- 마감은 지정 부서·해당 월에 적용합니다. 마감 후 수퍼관리자를 포함한 모든 사용자의 실적 입력·조정을 차단합니다.
- **관리자는 자신의 관리 부서, 수퍼관리자는 전체 부서의 마감을 해제**할 수 있습니다. 입력·조정·마감·해제·지표 수정·권한 변경에 사유와 변경 전후 값, 처리자, 시각을 남깁니다.
- 지표 수정은 지표명·단위·목표·배점·산식 설명을 지원합니다. 지표의 적용 부서·평가유형 변경이나 신설·삭제는 아직 제공하지 않습니다.
- 마감된 월의 지표 정의와 목표는 보존합니다. 부서별 목표·가중치 변경은 해당 연도의 미마감 실적에 반영하고 변경 이력을 남깁니다. 전체 공통 지표 정의 수정은 기존 실적에 자동 소급하지 않습니다.
- 목표·배점·산식 설명은 기준정보입니다. 편람의 복합 산식·예외를 적용하는 점수 계산 엔진은 후속 개발 범위입니다.
- 월 마감은 입력 잠금이며 전체 지표의 제출 완료를 자동 인정하는 절차는 아닙니다.
- 기존 계정 DB는 시작 시 자동으로 스키마를 확장하며 기존 계정의 권한은 직원으로 유지합니다.


## 내부망 실행

사내 인증기관에서 발급한 인증서와 키를 사용합니다.

```bash
python app.py --host 0.0.0.0 --port 8443 --cert server.crt --key server.key
```

직원은 인증서 이름과 일치하는 내부 DNS 주소로 접속합니다. 내부 서버 방화벽과 서비스 자동시작은 운영환경에 맞게 설정합니다.
HTTP 기본 실행은 로컬 확인용입니다. 직원이 접속하는 내부망 환경은 HTTPS로 구성합니다.

계정·설정·변경 이력은 `data/performance.sqlite3`에 저장됩니다. 서버를 종료하고 data 폴더를 백업하거나 운영 중 SQLite backup API를 사용합니다.
비밀번호나 세션 원문은 저장하지 않습니다. 서버 관리자는 DB와 인증서 개인키 접근권한을 제한해야 합니다.

## 테스트

```bash
python -m unittest -v test_app test_management test_entries test_review test_indicator_bulk
```

회원가입부터 재로그인 후 복원, 근무지 변경 이력, 서버 검증, 계정별 접근 분리, 만료 세션, 로그인 시도 제한을 검증합니다.
브라우저 화면 확인, 실제 내부망 배포 및 부하검증은 아직 수행하지 않았습니다.


## 실적 입력·목표 관리·증빙자료

월별 실적 목록에서 관리자는 **목표·가중치**, 직원은 **입력·수정** 버튼을 사용합니다.

- 목표·가중치는 **부서 × 연도 × 지표** 단위로 설정합니다. 수퍼관리자는 전체 부서, 관리자는 지정 부서만 수정할 수 있습니다.
- 수치형/서술형 입력, 목표치, 가중치(배점), 단위(건·명·% 등), 상향형/하향형 달성률 계산 방식을 설정합니다.
- 진행상태는 **미착수 / 진행중 / 완료** 중 선택합니다. 향후계획과 실적 설명도 저장합니다.
- 미착수·진행중에는 수치를 비워두고 계획부터 저장할 수 있습니다. 완료에는 수치형이면 실적 수치, 서술형이면 실적 내용이 필요합니다.
- 상향형 달성률은 **실적 ÷ 목표 × 100**, 하향형은 **목표 ÷ 실적 × 100**입니다. 관리자가 조정한 실적이 있으면 조정값을 기준으로 표시합니다.
- 예: 목표 20%, 실적 10%는 수치 20과 10으로 저장하고 달성률 50%로 표시합니다.
- 목표가 없거나 0 이하이면 달성률을 산정하지 않습니다. 하향형의 실적이 0 이하인 경우에도 별도 확인으로 표시합니다. 서술형은 달성률을 산정하지 않습니다.
- 달성률은 소수점 2자리로 표시하고 100%를 초과할 수 있습니다. 가중치를 곱한 평가점수나 편람의 복합 산식 점수는 계산하지 않습니다.
- 해당 월에 입력한 실적을 목표와 비교합니다. 월별 실적을 자동 합산하지 않으므로 누적 기준 관리 시 해당 월 기준 누적값을 입력합니다.
- 목표·가중치 변경은 같은 연도의 미마감 월에 반영하고, 마감월의 기존 목표·실적은 보존합니다. 실적이 이미 있는 지표의 수치형/서술형 전환은 차단합니다.

### 증빙 업로드·다운로드

1. 실적을 먼저 저장합니다. 미착수 상태와 빈 수치로도 저장할 수 있습니다.
2. 해당 실적의 **증빙** 버튼에서 파일을 선택해 업로드합니다.
3. 담당 직원·지정 부서 관리자·수퍼관리자가 인증 후 다운로드할 수 있습니다.

파일당 10MB, 지표·월별 활성 파일 최대 10개를 지원합니다. PDF, HWP/HWPX, 오피스 문서, PNG/JPG, TXT/CSV, ZIP을 지원합니다.
파일은 DB와 같은 data 폴더 아래 uploads에 임의 저장명으로 보관하고 원래 파일명·용량·SHA-256·등록자·시각을 기록합니다.
공개 정적 URL로 노출하지 않으며 다운로드 시에도 부서·담당지표 권한을 검사합니다. 마감 후 업로드·삭제는 차단하고 다운로드는 허용합니다.
삭제는 목록에서 숨기는 방식이며 원본과 감사기록은 보존합니다. 직원은 본인이 올린 증빙만 삭제하고 관리자는 해당 관리 범위 내 증빙을 삭제할 수 있습니다.
여러 파일 중 일부만 업로드에 성공하면 성공 개수와 오류를 표시하고 저장된 파일 목록을 다시 불러옵니다.
증빙파일과 계정 DB는 GitHub에 업로드하지 않습니다. 백업은 서버를 종료한 뒤 **data 폴더 전체**를 대상으로 합니다.


## 관리자·수퍼관리자의 월별 실적 확인

관리자 또는 수퍼관리자로 로그인하면 **월별 실적 확인** 메뉴와 기본 화면이 표시됩니다.
개인 실적 입력 화면인 **월별 실적 관리**와 구분됩니다.

- 관리자는 지정된 부서 직원 전체의 실적을 조회·수정합니다. 수퍼관리자는 전체 근무지 또는 선택한 근무지로 조회합니다.
- 근무지별 현황, 직원별 입력 현황, 직원 지표별 실적을 각각 표시합니다. 수치·서술 내용, 달성률, 진행상태, 향후계획, 증빙을 확인합니다.
- **미입력**은 저장된 실적이 없는 경우, **임시저장**은 계획 등만 저장하고 수치/서술 실적이 없는 경우, **입력완료**는 실제 수치 또는 서술 내용이 있는 경우입니다. 숫자 0도 입력된 실적으로 인정합니다.
- 입력완료 여부와 진행상태의 완료는 다른 항목입니다. 직원 입력률은 입력완료 건수 ÷ 담당지표 건수입니다.
- 근무지의 평균 달성률은 계산 가능한 수치형 실적의 단순평균이며 가중치를 적용한 평가점수가 아닙니다.
- 같은 지표를 여러 직원이 맡아도 **직원 × 근무지 × 연도 × 월 × 지표**별 실적을 별도로 저장합니다. 다른 직원의 입력을 덮어쓰지 않습니다.
- 관리자는 미입력 직원의 담당지표를 대리 입력하거나 기존 실적·진행상태·향후계획을 수정할 수 있습니다. 입력 직원은 유지하고 수정자와 변경 사유·전후 값을 감사이력에 남깁니다.
- 관리자 수정 화면에서 저장하면 기존 수치 조정값은 해제되고 새 입력 실적이 반영됩니다. 수치 조정 기능은 원래 값과 조정값을 별도로 보관합니다.
- 관리자도 소속 관리 부서의 월별 취합을 마감·해제할 수 있습니다. 마감 상태에서는 직원과 관리자 모두 실적·증빙을 변경할 수 없습니다.
- 월별 실적은 현재 담당지표와 선택 월에 이미 저장된 과거 담당 실적을 함께 조회합니다. 이전 소속·담당 실적은 표시를 구분해 보존합니다.
- 증빙은 본인의 실적 또는 관리 권한이 있는 부서의 실적에 한해 접근합니다. 같은 지표를 담당하는 다른 직원에게 증빙을 공개하지 않습니다.

### XLSX 다운로드

조회 중인 연도·월·근무지 범위로 다운로드합니다. 관리자는 해당 부서, 수퍼관리자는 전체 또는 선택한 근무지를 내보냅니다.

| 엑셀 시트 | 내용 |
| --- | --- |
| 근무지현황 | 직원 수, 담당 건수, 입력완료·미입력·임시저장, 참고 평균 달성률, 마감 상태 |
| 직원입력현황 | 사번·성명, 담당·입력 건수, 입력률, 현재/이전 소속 |
| 지표실적 | 목표·가중치·실적·달성률·진행상태·향후계획·증빙파일명·수정자·마감 상태 |

사번은 텍스트로 보존하여 앞자리 0이 사라지지 않으며, 숫자와 달성률은 Excel 숫자/백분율로 저장합니다.
사용자가 작성한 실적 설명·계획 등은 Excel 수식으로 실행되지 않도록 텍스트 셀로 저장합니다.
다운로드 파일과 실제 증빙·계정 DB는 GitHub에 저장하지 않습니다. 서버는 외부 패키지 없이 표준 라이브러리로 XLSX를 생성합니다.

### 기존 자료 전환

직원별 실적 구조로 처음 전환할 때 data/backups에 DB 사본을 만들고 기존 실적 ID와 증빙 연결을 보존합니다.
기존 실적의 최초 입력 감사이력을 기준으로 입력 직원을 연결합니다. 해당 이력이 없으면 최종 수정자를 기준으로 연결하고 화면에 **기존 담당자 추정**을 표시합니다.
서버 시작 시 자동 전환되므로 기존 Codespace에서는 최신 코드를 받은 후 컨테이너를 재시작합니다.


## 수퍼관리자 지표 일괄 수정과 권한 제어

### 전체 지표 관리

수퍼관리자 메뉴의 **전체 지표 관리**에서 공통 지표를 표 형태로 확인합니다.
지표명·지표ID·적용부서 검색, 기관유형·평가유형 필터를 제공하며 각 행의 **수정** 버튼으로 지표명·단위·기본 목표·가중치(배점)·산식 설명을 수정합니다.
근무지별로 별도 설정한 목표·가중치는 공통 기본값보다 우선합니다.

### XLSX로 전체 수정

1. 평가연도를 선택하고 **수정 양식 다운로드**를 누릅니다.
2. 양식의 노란색 셀을 수정한 뒤 XLSX로 저장합니다. 회색 항목과 시트명·제목 행·전체 행은 유지합니다.
3. **업로드 · 변경 미리보기**에서 행별 검증과 변경 전후 내용을 확인합니다.
4. 일괄 수정 사유를 입력하고 **확인한 변경사항 일괄 반영**을 누릅니다.

| 양식 시트 | 수정 항목 |
| --- | --- |
| 지표정의 | 전체 공통 지표의 지표명·단위·목표·가중치(배점)·산식 및 평가기준 |
| 부서별목표 | 선택 연도의 근무지·지표별 목표·가중치·단위·수치형/서술형·상향형/하향형 |
| 사용안내 | 작성 및 반영 규칙 |

- 파일은 5MB 이하의 XLSX를 지원합니다. Excel 공유 문자열과 일반 숫자·백분율 셀을 읽으며 수식은 값으로 붙여넣기 한 후 업로드합니다.
- 단위가 %인 목표는 숫자 20 또는 Excel 백분율 20%로 입력할 수 있습니다. 가중치는 백분율이 아닌 배점 숫자로 입력합니다.
- 노란색 입력 셀은 편집할 수 있고 회색 ID·버전·기관·근무지·연도·평가유형은 변경하지 않습니다. 신규 지표 추가·삭제와 행 누락은 허용하지 않습니다.
- 공통 지표와 부서별 목표의 버전을 검사합니다. 다른 사람이 먼저 수정했거나 마감 상태가 바뀌면 최신 양식/미리보기로 다시 검증합니다.
- 오류가 있으면 전부 반영하지 않습니다. 유효한 변경도 미리보기 단계에서는 저장하지 않으며, 일괄 반영은 하나의 DB 트랜잭션으로 처리합니다.
- 미리보기는 실행한 수퍼관리자의 로그인 세션에 연결하고 15분 동안 유효합니다. 재로그인하거나 이미 반영한 미리보기는 다시 사용할 수 없습니다.
- 부서별 변경은 같은 연도의 미마감 월에 반영하고 마감월은 보존합니다. 모든 월이 마감된 부서의 변경은 차단합니다.
- 공통 기본값 수정은 부서별 별도 설정이나 기존 실적에 자동 소급하지 않습니다. 실적·증빙·직원 담당 배정·권한은 이 양식에서 삭제하지 않습니다.
- 모든 변경은 사유·처리자·변경 전후 값과 함께 감사이력으로 남깁니다. 별도 외부 Excel 패키지 없이 서버 표준 라이브러리로 동작합니다.

### 관리자 권한 제어

관리자 권한 지정 기능은 지표 수정 화면에서 분리하여 **관리자 권한 제어** 메뉴로 제공합니다.
수퍼관리자만 직원의 권한과 관리 부서를 지정할 수 있습니다. 권한 변경 후 대상 계정은 다시 로그인해야 합니다.
기존 **근무지·지표 변경 이력** 메뉴와 화면은 제거했습니다. 저장된 변경·감사기록은 보존합니다.

## 후속 개발 범위

직원 여부 확인을 위한 인사명부 대조·가입 승인, 비밀번호 재설정, 계정 비활성화,
편람에 따른 평가점수 자동 계산·평가위원 채점은 아직 포함하지 않았습니다.
사번을 직접 입력하는 가입 방식이므로 실제 직원 운영 전 계정 확인 절차를 구성해야 합니다.

향후 실적 데이터에는 작성 당시 부서와 지표·양식 버전을 별도로 저장해야 하며,
인사이동 시 과거 실적의 소속이 바뀌지 않도록 설계합니다.
